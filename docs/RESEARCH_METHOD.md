# خطة المنهجية البحثية (مقترح، ليست نتائج)

## سؤال البحث

كيف نحسّن **دقة المعنى والمصطلحات وجودة الكلام والتزامن** في دبلجة فيديوهات تعليمية من الإنجليزية إلى العربية ضمن منظومة آلية، مع مراقبة أثر الأخطاء المتراكمة بين المراحل؟

هذه فرضية عمل تحتاج مراجعة أدبيات أوسع؛ **ليست ادعاء بأن المشروع أول نظام EN→AR**.

## نطاق التجارب

فيديوهات تعليمية إنجليزية بمُحاضر أساسي واحد في المرحلة الأولى. لا تشمل التجارب الحالية فصل المتحدثين أو حل الكلام البشري المتداخل. فصل الكلام عن الخلفية (موسيقى/ضجيج) مختلف عن فصل المتحدثين.

## Baselines وAblations المقترحة

| سؤال التجربة | مقارنة مقترحة | مقاييس محتملة |
|---|---|---|
| هل الفصل يحسن التفريغ؟ | صوت خام ↔ كلام مفصول | WER مقابل تفريغ مرجعي؛ ومقاييس جودة فصل عند وجود مرجع |
| هل يساعد فهم السياق؟ | ترجمة عادية ↔ سياقية مع قاموس مصطلحات | chrF++ / COMET + دقة المصطلحات مقابل مراجع مستقلة |
| هل يساعد ضبط المدة؟ | TTS بلا ضبط ↔ TTS بضبط المدة | Duration Error مع فحص أثر الضبط على المعنى وجودة الصوت |
| ما أثر الجمع بين المكونات؟ | نظام مرجعي ↔ خيارات Ablation | قياسات كل مرحلة + زمن المعالجة وإكمال الفيديو والتكلفة |

## منهجية التحقق

- نثبّت مجموعة فيديوهات الاختبار ونتجنب تسرّب فيديوهات التدريب إلى الاختبار.
- نحتفظ بمراجع نصية وصوتية مستقلة عند استخدام مقاييس تتطلب مرجعًا.
- نسجّل لكل تجربة: الإصدار، إعدادات النموذج، Dataset split، Run ID، بصمات الملفات، المدة، تكلفة التشغيل، وأسباب الإخفاق.
- نفرّق بين تقييم آلي ضمن الـPipeline (دون مراجعة بشرية داخل التشغيل) وبين الاختبارات البحثية المستقلة.
- لا نعلن وجود تحسن قبل ظهور نتائج قابلة للإعادة وتحليل الخطأ.

## حدود المشروع

مزامنة الشفاه تُفعّل فقط عندما يوجد وجه مناسب. جودة الترجمة لا تختزل في مقياس نصي واحد، وتطابق المدة وحده لا يثبت طبيعية الصوت أو صحة المعنى.

## هدف المنتج

تقييم قابلية التشغيل الواقعية من حيث التراخيص وحقوق المحتوى والخصوصية والتكلفة والزمن والاستقرار؛ هذه أهداف تقييم وليست مزايا مثبتة حاليًا.
